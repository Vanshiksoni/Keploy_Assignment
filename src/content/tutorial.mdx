<h2 id="overview">Overview & Why Keploy?</h2>

As a Go developer building microservices with frameworks like **Echo**, writing unit tests and mocking database calls (such as PostgreSQL or MySQL) is historically tedious and time-consuming. You often spend more time writing boilerplate test suites, maintaining SQL mock interfaces, and syncing fixtures than shipping feature code.

**Keploy changes this paradigm completely.** 

Instead of writing manual unit tests or maintaining fragile mocks, Keploy acts as an **e2e test generator**. By intercepting network traffic (HTTP calls) and database protocols (PostgreSQL wire format) while your application runs, Keploy records incoming API requests and external dependency responses. It saves them as clean, version-controlled **YAML test cases**.

<Callout type="tip" title="Why is this huge for Go developers?">
  Go is strictly typed and relies heavily on interfaces for mocking (e.g., `pgx`, `database/sql`). Keploy eliminates the need to rewrite database driver interfaces or build mock databases. You test the exact compiled Go binary against real network traffic!
</Callout>

<h2 id="prerequisites">Prerequisites</h2>

Before starting this quickstart, ensure you have the following installed on your system:

- **Go 1.20+** installed on your machine (`go version`).
- **Docker & Docker Compose** (to run the PostgreSQL database container).
- **cURL** or **Postman** for sending sample HTTP requests.
- **Linux, macOS, or WSL2** (Keploy utilizes eBPF/proxy capabilities for zero-code network interception).

<Callout type="info" title="Under the Hood: SQL Wire Interception">
  When your Echo app executes a SQL query via `database/sql` or `pgx`, PostgreSQL speaks the Postgres Wire Protocol over TCP port 5432. Keploy intercepts this binary protocol, storing both the query and the resulting SQL rows in YAML format. When replaying tests with <code>keploy test</code>, Keploy feeds these exact SQL rows back to your Go app—meaning **you don't even need PostgreSQL running during test runs!**
</Callout>

<h2 id="step-1-app-setup">Step 1: Echo + Postgres URL Shortener App Setup</h2>

Let's set up the sample URL shortener application built with the **Echo** web framework and **PostgreSQL**.

Clone the official quickstart repository or create a new Go application:

<CodeBlock
  filename="terminal"
  language="bash"
  code={`# Clone the sample Go repository
git clone https://github.com/keploy/samples-go.git
cd samples-go/echo-postgres

# View the project directory structure
ls -la`}
/>

Here is a snippet of how the Echo application (`main.go`) initializes the Postgres connection and exposes the URL shortener routes:

<CodeBlock
  filename="main.go"
  language="go"
  code={`package main

import (
	"database/sql"
	"net/http"
	"github.com/labstack/echo/v4"
	_ "github.com/lib/pq"
)

type URLRecord struct {
	URL string \`json:"url"\`
}

func main() {
	// 1. Connect to PostgreSQL
	db, err := sql.Open("postgres", "postgres://postgres:password@localhost:5432/urlshortener?sslmode=disable")
	if err != nil {
		panic(err)
	}
	defer db.Close()

	// 2. Initialize Echo Router
	e := echo.New()

	// Route: Shorten URL (POST /shorten)
	e.POST("/shorten", func(c echo.Context) error {
		var req URLRecord
		if err := c.Bind(&req); err != nil {
			return c.JSON(http.StatusBadRequest, echo.Map{"error": "invalid payload"})
		}
		
		shortCode := "k3p9L" // Generated short code
		_, err := db.Exec("INSERT INTO urls (short_code, original_url) VALUES ($1, $2)", shortCode, req.URL)
		if err != nil {
			return c.JSON(http.StatusInternalServerError, echo.Map{"error": "db error"})
		}

		return c.JSON(http.StatusOK, echo.Map{"short_url": "http://localhost:8080/" + shortCode})
	})

	e.Logger.Fatal(e.Start(":8080"))
}`}
/>

<h2 id="step-4-recording-tests">Step 4: Record API Tests with `keploy record`</h2>

Now comes the magic! Compile your Go app binary and run it through `keploy record`.

<CodeBlock
  filename="terminal"
  language="bash"
  code={`# 1. Build the Go binary
go build -o main main.go

# 2. Run Keploy in recording mode
sudo keploy record -c "./main"`}
/>

While Keploy is running and monitoring traffic, open a separate terminal window to send HTTP API requests:

<CodeBlock
  filename="terminal"
  language="bash"
  code={`# Send a POST request to shorten a URL
curl -X POST http://localhost:8080/shorten \\
  -H "Content-Type: application/json" \\
  -d '{"url": "https://keploy.io"}'

# Expected Response:
# {"short_url": "http://localhost:8080/k3p9L"}`}
/>

Press `Ctrl + C` in the Keploy recording terminal to stop the session.

<Callout type="tip" title="What just happened?">
  Keploy intercepted both the incoming HTTP <code>POST /shorten</code> request AND the resulting <code>INSERT INTO urls</code> SQL query sent to PostgreSQL. It saved a complete test case and SQL mock under the <code>./keploy</code> directory!
</Callout>

---

<h2 id="step-5-testing-mocking">Step 5: Replay Tests & Dependency Mocks with `keploy test`</h2>

Now, stop your PostgreSQL database container (`docker-compose down`). We will run tests **without any database server running!**

<CodeBlock
  filename="terminal"
  language="bash"
  code={`# Stop the PostgreSQL database
docker-compose down

# Run automated tests using saved Keploy mocks
sudo keploy test -c "./main" --delay 10`}
/>

Keploy spins up your Go binary, intercepts PostgreSQL connection attempts, and injects the recorded SQL response data automatically!

<h2 id="devrel-insights">DevRel Insights & "Aha!" Moments</h2>

During our testing of the Echo + PostgreSQL quickstart, we uncovered several valuable insights for Go engineers:

1. **Zero Code Changes**: You don't need to import any Keploy SDK inside `main.go`. Keploy works entirely at the network packet proxy layer.
2. **Speed & CI Integration**: Running tests with recorded PostgreSQL mocks takes milliseconds compared to spinning up heavy Docker containers in GitHub Actions CI pipelines.
3. **Determinism**: Random values (like timestamps or UUIDs) can be masked in Keploy YAML configs so tests never fail due to transient data differences.
